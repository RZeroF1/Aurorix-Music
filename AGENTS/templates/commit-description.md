# Version Update Description Template

Use this release-style template for public release notes and substantial commit
descriptions. Write for people who need to understand what changed, where it
changed, and what was actually verified. Every line must be safe to retain in a
public Git history.

```text
功能更新:

- [<平台或领域>] <新增的用户或开发者可用能力。>

质量更新:

- [<平台或领域>] <修复、稳定性、性能、可访问性或体验改进，以及可观察结果。>

架构更新:

- [<平台或领域>] <边界、合同、依赖、生命周期、构建门禁或可维护性变化。>

安全更新:

- [<平台或领域>] <已修复或收紧的安全边界；不公开未修复漏洞细节、真实端点或凭据。>

兼容性与迁移:

- <无破坏性变更，或说明受影响接口、数据迁移、回滚路径与用户操作。>

验证范围:

- 已验证：<实际执行的测试、检查或人工验证，以及结果。>
- 未验证：<尚未执行的范围与具体原因。>

已知限制:

- <平台、硬件、网络或功能限制；没有时删除此节。>
```

## 标签规则

每条更新以一个或两个中括号标签开头。第一个标签标记平台或交付面，第二个标签可选，用于标记
具体领域。

| 平台或交付面 | 可选领域标签 |
|---|---|
| `[通用]` | `[治理]`、`[文档]`、`[构建/CI]` |
| `[Core]` | `[模型]`、`[存储]`、`[媒体库]`、`[播放]`、`[音频]`、`[同步]` |
| `[Windows]` | `[UI]`、`[平台适配]`、`[播放]`、`[音频]` |
| `[Android]` | `[UI]`、`[媒体服务]`、`[平台适配]`、`[播放]` |
| `[Cloud]` | `[API]`、`[同步]`、`[账户]`、`[存储]` |
| `[Provider]` | `[宿主]`、`[SDK]`、`[包策略]` |
| `[FFI]` | `[C ABI]`、`[UniFFI]`、`[绑定生成]` |
| `[Web]` | `[管理]`、`[控制台]` |

Examples:

```text
- [Windows][UI] 本地音乐库页面显示来自 Core 的搜索结果快照。
- [Android][媒体服务] 媒体控制命令通过服务 Host 路由到共享 Core。
- [Core][媒体库] 扫描结果按确定性规则生成搜索索引。
- [Cloud][同步] 增加版本化同步响应的合同验证。
- [通用][构建/CI] 固定 Rust 工具链并在持续集成中执行格式化检查。
```

## 分类规则

- **功能更新**：新增或扩大已可用能力。不要把尚未实现的计划写成更新。
- **质量更新**：修复缺陷，或改善稳定性、性能、可访问性、可观测性与使用体验。描述结果，不只
  写“优化”。
- **架构更新**：说明不直接可见但影响边界、合同、模块职责、生命周期、生成链路或工程门禁的变化。
  需要写明动机；不把无关重构混在功能条目里。
- **安全更新**：说明已完成的防护、依赖修复或权限收紧。未修复漏洞的复现、真实服务信息和任何
  凭据都不进入公开更新说明。

按“功能、质量、架构、安全”的固定顺序排列；没有内容的类别删除，不要填入“无”。单次提交只
描述一个可审查目的。跨平台变更分别列条目，例如 `[Core]` 与 `[Windows]`，而不是笼统写成
“多端支持”。
